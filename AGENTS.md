Bradley's public portfolio, bradleyberkman.com: a vinext app with a map, a reader and a chat assistant, served by one Cloudflare Worker.
The check is `npm test`: typecheck, lint, vitest, the studio tests, then a full build and `test:rendered`, which proves the sentinel keys never reach the client bundle.
Layers, lowest first; each imports only itself and those before it: `lib/` (browser-safe types and logic) with `content/`, then `lib/server/`, then `worker/` (which also runs the insights pipeline in `scripts/portfolio-insights-*.mjs`) on one side and `components/` then `app/` on the other; `lib/` and `components/` never import `lib/server/` or `worker/`. `tests/layers.test.ts`, in the check, fails an import going the other way and names the module to use instead.
A merge to main deploys to production automatically (bradleyberkman.com, www and insights.braininavat.dance); the Worker `bradley-portfolio-main-preview` and everything named "main-preview" is production, not a preview.
Live: `npm run live` checks production read-only (every route and surface, a headless pass that fails on console errors and failed requests, the reading-room checks; `-- --dist <tested dist>` also proves the deployed build). Both deploys run it after deploying; any live check you would otherwise improvise belongs in `scripts/live.mjs`.
Cloud agents reproduce bugs with repo secrets, never printed: `CLOUDFLARE_OBSERVABILITY_TOKEN` (read-only Workers logs, which `scripts/portfolio-chat-logs.mjs` reads), `LINEAR_API_KEY` (Personal and BIV teams) and the org's `CLAUDE_CODE_OAUTH_TOKEN`.
Copy lives in `content/portfolio-content.json`; before UI work read `docs/design-conventions.md` and the component's sheet in `docs/components/`; social video is a JSON spec in `scripts/clip-studio/specs/` (see `docs/clip-studio.md`).
